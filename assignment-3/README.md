# Decisions I made and why

I made four tables: `artists`, `songs`, `playlists` and `playlist_songs`. The last one is a link table, because a song can be in many playlists and a playlist has many songs, so that relationship can't live in a single column of `songs` or `playlists`. Its primary key is the pair `(playlist_id, song_id)`, which also enforces "a song does not repeat inside one playlist", and the order is stored in a `position` column on this table (not in `songs`) because the order is different for every playlist; `UNIQUE (playlist_id, position)` stops two songs from taking the same slot. Every song has exactly one artist, so `songs.artist_id` is a foreign key to `artists` instead of repeating the artist name as text, and all the keys use `REFERENCES` so the database refuses ids that don't exist. Duration is stored as an `INTEGER` number of seconds (with `CHECK > 0`) so it can be added up with `SUM`, and the `mm:ss` format is made only when a query displays it. I deliberately do not store the total duration or the number of songs of a playlist, because they can be calculated from the other tables and a stored copy could become wrong when a song is added or removed; I also don't store albums, genres or users because the task doesn't ask for them.
